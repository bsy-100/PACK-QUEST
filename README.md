# PACK QUEST

여행 조건을 고르면 준비물 목록을 만들어 주고, 공유 코드로 초대한 친구들과 담당을 나눠 함께 체크하는 웹앱이다. AWS에 3티어(웹·앱·DB)로 구축한다.

- 기간: 2026-10-19(월) ~ 10-23(금), 금요일 라이브 데모 발표
- 팀: A 인프라·MariaDB, B 백엔드, C 프론트엔드·발표
- 기준 문서: PACK QUEST PRD(최종본), PACK QUEST API 명세(2026-10-19 확정), [MVP 기획서](docs/mvp-plan.md)

## 주요 기능

| 기능 | 내용 |
|---|---|
| 여행 만들기 | 국내/해외, 이동수단, 기간, 계절을 고르면 공유 코드와 준비물 목록이 만들어진다 |
| 코드로 참여 | 공유 코드와 닉네임으로 입장한다. 로그인 없이 참여할 때 받은 토큰으로 사람을 구분한다 |
| 함께 챙기기 | 한 명이 챙기면 되는 공용 준비물. 담당을 나눠 맡고, 담당자가 완료를 체크한다. 팀 진행률에 반영된다 |
| 내 짐 | 여권·칫솔처럼 각자 챙기는 개인 준비물. 이 기기에만 저장되고 팀원에게는 보이지 않는다 |
| 팀 진행률 | 전체 완료율과 참여자별 완료율. 5초마다 자동으로 갱신된다 |
| 주최자 기능 | 다른 참여자에게 담당 배정, 항목 삭제, 여행 삭제 |

## 아키텍처

```
브라우저 ─▶ CloudFront ─┬─(화면)────▶ S3 (비공개, OAC)
                        └─(/api/*)──▶ EC2 FastAPI (프라이빗 서브넷, 0.0.0.0:8000)
                                          │ 3306
                                          ▼
                                     EC2 MariaDB (프라이빗 서브넷)
```

- 인터넷에서 서버로 들어오는 길은 CloudFront뿐이다(VPC 오리진). 두 서버는 공인 IP가 없고, 밖으로 나가는 통신은 NAT Gateway로만 한다.
- 서버 접속은 SSM Session Manager로만 한다(22번 포트 없음).
- DB 비밀번호는 Parameter Store에 두고, 저장소에는 비밀번호·키·`.env`를 올리지 않는다.
- 모든 리소스는 AWS 콘솔에서 직접 만든다. IaC와 자동 배포(CI/CD)는 쓰지 않는다.

## 폴더 구조

| 폴더 | 내용 | 담당 |
|---|---|---|
| `frontend/` | 화면(HTML/CSS/JavaScript). 이 폴더 안의 파일만 S3에 올린다 | C |
| `backend/` | FastAPI 앱, 추천 규칙(`app/data/recommend_rules.json`), 배포 설정 | B |
| `db/` | `schema.sql` | B·A |
| `docs/` | 기획서, API 응답 예시 등 문서 | 공동 |
| `tools/` | 로컬 개발용 도구. S3에 올리지 않는다 | C |

`frontend/` 안의 구성:

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면 4개(시작, 여행 만들기, 참여, 체크리스트)를 한 파일에서 전환 |
| `css/style.css` | 반응형 스타일. 휴대폰 기본, 900px 이상에서 체크리스트 2단 배치 |
| `js/constants.js` | 코드값의 한글 표시, 오류 코드별 안내 문구 |
| `js/api.js` | API 호출, `X-Pack-Token` 헤더, 토큰 보관 |
| `js/personal.js` | 내 짐(개인 준비물) 목록과 브라우저 저장 |
| `js/mock.js` | 주소에 `?mock=1`이 있을 때만 켜지는 가짜 서버 |
| `js/app.js` | 화면 전환, 체크리스트 그리기, 버튼 동작, 5초 폴링 |

## 로컬에서 실행하기

### 화면만 보기 (서버 없이)

Node.js만 있으면 된다. 저장소 맨 위 폴더에서:

```bash
node tools/dev-server.mjs
```

브라우저에서 http://localhost:5500/?mock=1 을 연다.

- `?mock=1`이면 브라우저 안의 가짜 서버(`js/mock.js`)가 API 명세대로 응답한다.
- 체험용 여행 코드 `PACK2345`로 바로 참여해 볼 수 있다.
- 가짜 데이터 초기화: 브라우저 콘솔(F12)에서 `PQ.mock.reset()`

### 실제 API와 연결하기

1. B의 안내(`backend/README.md`)대로 FastAPI를 실행한다(기본 http://127.0.0.1:8000).
2. 다른 터미널에서 `node tools/dev-server.mjs`를 실행하고 http://localhost:5500/ 을 연다.

`dev-server.mjs`는 화면 파일을 보내고 `/api/*` 요청만 FastAPI로 넘긴다. 배포 환경에서 CloudFront가 하는 일을 로컬에서 흉내 내는 것이라 화면 코드를 고치지 않아도 된다. 다른 PC의 서버로 넘기려면 `--api http://<주소>:8000`을 붙인다.

## 배포

자동 배포는 쓰지 않는다. 배포할 때마다 배포한 사람, 시간, 커밋을 팀 채팅에 남긴다.

| 대상 | 방법 | 담당 |
|---|---|---|
| 화면 | `frontend/` 안의 파일을 AWS 콘솔에서 S3 버킷에 업로드하고, 화면이 바뀌지 않으면 CloudFront 캐시 무효화 | C |
| 백엔드 | SSM으로 Backend 서버에 접속해 `git pull` 후 서비스 재시작(`backend/deploy/DEPLOY.md`) | B |
| DB | DB 서버에서 `schema.sql` 실행, 앱 전용 계정에 최소 권한 | A |

## 협업 규칙

- 작업은 각자 브랜치(`feature/frontend`, `feature/api` 등)에서 하고 3일 차에 `main`으로 합친다. 합치기 전에 다른 팀원이 한 번 확인한다.
- 작업 전에 최신 내용을 받는다(`git pull`).
- 비밀번호, 키, `.env` 파일은 올리지 않는다(`.gitignore` 확인).
- 각자 맡은 폴더만 수정한다. 다른 사람의 폴더를 고쳐야 하면 먼저 담당자와 이야기한다.
