# 로그인 API (선택 기능)

> `feature/auth` 브랜치. 기존 API 9개([API_SPEC.md](API_SPEC.md))는 **그대로** 동작한다. 로그인은 선택이고, 비로그인 사용자는 지금처럼 쓰면 된다.

## 한눈에

| 토큰 | 헤더 | 받는 곳 | 쓰는 곳 |
|---|---|---|---|
| 여행 토큰 (기존) | `X-Pack-Token` | 여행 만들기·참여·재발급 응답의 `token` | 여행 안의 모든 API (조회, 맡기, 체크…) |
| 로그인 토큰 (새로) | `X-Auth-Token` | 회원가입·로그인 응답의 `token` | `/api/me…`, 로그아웃, 여행 만들기·참여(계정 연결) |

- 로그인 토큰은 30일 동안 유효하다. 브라우저에 저장해 두고 쓴다.
- 여행 안의 권한(주최자/담당자)은 계속 `X-Pack-Token`으로 판단한다. 로그인은 "내 여행 목록"과 "다른 기기에서 다시 들어가기"를 위한 것이다.
- 오류 형식은 기존과 같다: `{"detail": {"code", "message"}}`

## 값 규칙

| 값 | 규칙 |
|---|---|
| `username` | 영문·숫자·밑줄 4~20자. 대문자로 보내도 **소문자로 저장**된다 (`JunHo` → `junho`) |
| `password` | 8~64자 |
| `nickname` | 기존과 같음(앞뒤 공백 제거 후 1~20자). 계정의 기본 닉네임으로, 여행 만들 때 닉네임 칸에 미리 채워 주면 된다 |

## API

### A1. 회원가입 `POST /api/auth/signup`

```json
{"username": "junho", "password": "password1", "nickname": "준호"}
```

`201` — 가입과 동시에 로그인된다.

```json
{"token": "로그인 토큰", "user": {"user_id": 1, "username": "junho", "nickname": "준호"}}
```

| 오류 | 언제 |
|---|---|
| `409 USERNAME_TAKEN` | 이미 있는 아이디 |
| `422 VALIDATION_ERROR` | 값 규칙 위반 |
| `429 RATE_LIMITED` | 같은 IP에서 1분에 30회 초과(가입·로그인 합산) |

### A2. 로그인 `POST /api/auth/login`

```json
{"username": "junho", "password": "password1"}
```

`200` — 응답 형식은 A1과 같다. 로그인할 때마다 새 토큰이 나오고, 다른 기기의 로그인은 그대로 유지된다.

| 오류 | 언제 |
|---|---|
| `401 LOGIN_FAILED` | 아이디가 없거나 비밀번호가 틀림 (둘을 구분하지 않는다) |
| `429 RATE_LIMITED` | A1과 같음 |

### A3. 로그아웃 `POST /api/auth/logout`

헤더 `X-Auth-Token`. `204`, 본문 없음. 이 기기의 로그인 토큰만 지운다. 화면에서는 저장한 로그인 토큰을 지운다(여행 토큰은 그대로 둬도 된다).

### A4. 내 정보·내 여행 목록 `GET /api/me`

헤더 `X-Auth-Token`. `200`

```json
{
  "user": {"user_id": 1, "username": "junho", "nickname": "준호"},
  "trips": [
    {
      "code": "K7M3QX9P",
      "region": "overseas", "transport": "plane", "duration": "short", "season": "summer",
      "created_at": "2026-10-21T00:37:27Z",
      "me": {"member_id": 12, "nickname": "준호", "is_host": true},
      "progress": {"total": 22, "done": 5, "rate": 23}
    }
  ]
}
```

- `trips`는 최근에 참여한 순서. 삭제된 여행은 빠진다. 참여한 여행이 없으면 `[]`.
- 로그인하고 만들거나 참여한 여행만 나온다(로그인 전에 들어간 여행은 연결되지 않는다).

### A5. 다른 기기에서 다시 들어가기 `POST /api/me/trips/{code}/token`

헤더 `X-Auth-Token`, 본문 없음. `200` — 응답 형식은 기존 "참여"(3번)와 같다.

```json
{"code": "K7M3QX9P", "token": "새 여행 토큰", "me": {"member_id": 12, "nickname": "준호", "is_host": true}}
```

- 받은 `token`을 그 여행의 `X-Pack-Token`으로 저장하고 여행 화면으로 들어가면 된다.
- **주의:** 새 토큰이 발급되면 그 여행에 쓰던 **예전 기기의 여행 토큰은 더 이상 쓸 수 없다**(`401 TOKEN_INVALID`). 예전 기기에서 이 오류가 나면 "다른 기기에서 접속해 이 기기는 나갔습니다. 다시 로그인해 주세요"처럼 안내하고, 로그인 상태라면 A5를 다시 부르면 된다.

| 오류 | 언제 |
|---|---|
| `404 TRIP_NOT_FOUND` | 내가(이 계정으로) 참여한 여행이 아님 |

### 공통 오류 (A3~A5, 그리고 로그인 토큰을 보낸 기존 1·3번)

| 오류 | 언제 |
|---|---|
| `401 AUTH_MISSING` | `X-Auth-Token` 없음 (A3~A5) |
| `401 AUTH_INVALID` | 로그인 토큰이 틀렸거나 만료됨, 로그아웃한 토큰 → 저장한 로그인 토큰을 지우고 로그인 화면으로 |

## 기존 API에서 바뀐 점

- **1번 여행 만들기, 3번 참여:** 요청에 `X-Auth-Token`을 붙이면 그 참여자가 계정에 연결된다(A4 목록에 나옴). 요청 본문·응답은 그대로다.
  - 틀린 로그인 토큰을 붙이면 무시하지 않고 `401 AUTH_INVALID`를 준다.
  - 같은 계정으로 같은 여행에 두 번 참여하면 `409 ALREADY_JOINED` → A5로 다시 들어가면 된다.
- 로그인 없이 부르면 지금과 완전히 같다.

## 화면 흐름 예시

1. 첫 화면: "로그인 없이 시작" / "로그인" 두 버튼. 비로그인은 지금 흐름 그대로.
2. 로그인 후 첫 화면: A4의 `trips`로 "내 여행" 목록 + "새 여행 만들기" / "코드로 참여".
3. 목록에서 여행을 누르면: 이 기기에 그 여행 토큰이 있으면 바로 들어가고, 없으면 A5로 받아서 들어간다.
