# PACK QUEST MVP 기획서

- 작성일: 2026-10-19
- 기준 문서: PACK QUEST PRD(최종본), PACK QUEST API 명세(2026-10-19 확정)
- 이 문서는 두 기준 문서를 요약한 것이다. 내용이 다르면 기준 문서를 따른다.

## 1. 개요

PACK QUEST는 여행 조건을 입력하면 준비물 목록을 자동으로 만들어 주고, 공유 코드로 초대한 친구들과 담당자를 나눠 함께 체크하는 웹앱이다. AWS에 3티어(웹·앱·DB)로 구축한다.

| 항목 | 내용 |
|---|---|
| 문제 | 단체 여행 준비물이 메신저에 흩어져 있어 누가 무엇을 챙기는지 불분명하고, 중복과 누락이 생긴다. |
| 해결 | 조건별 추천 목록, 담당자 지정, 완료 체크, 팀 진행률을 한 화면에서 함께 본다. |
| 프로젝트 목표 | AWS 3티어 구축 실습(S3·CloudFront, EC2 FastAPI, EC2 MariaDB)과 바이브 코딩 실습. 기능은 단순하게 두고 인프라 구축에 무게를 둔다. 모든 리소스는 AWS 콘솔에서 직접 만들며 IaC와 CI/CD는 쓰지 않는다. |
| 기간 | 2026-10-19(월) ~ 10-23(금), 5일. 금요일에 라이브 데모로 발표한다. |
| 팀 | A 인프라·MariaDB, B 백엔드, C 프론트엔드·발표 |

## 2. 사용자와 역할

준비물을 나눠 챙겨야 하는 모든 여행 그룹(친구, 가족, 동아리 등)이 대상이다. 로그인은 없고, 여행을 만들거나 참여할 때 발급되는 토큰으로 사람을 구분한다.

| 역할 | 하는 일 | 권한 |
|---|---|---|
| 주최자 | 여행 생성, 공유 코드 전달, 담당자 배정, 항목·여행 삭제 | 여행을 만들 때 받은 토큰. 주최자도 닉네임으로 참여자 목록에 등록되며 `is_host`로 구분한다. |
| 참여자 | 코드로 입장, 항목 추가, 담당 항목 선택, 완료 체크 | 참여할 때 받은 토큰 |

- 참여자는 자기 자신에게만 항목을 배정할 수 있고, 다른 사람에게 배정하는 것은 주최자만 할 수 있다.
- 완료 체크는 주최자를 포함해 그 항목의 담당자만 할 수 있다.

## 3. MVP 범위

| 구분 | 항목 |
|---|---|
| MVP 필수 (FR-01~07) | 여행 생성, 조건별 준비물 추천, 공유 코드로 참여, 준비물 관리(추가·삭제), 담당자 지정과 완료 체크, 팀 진행률 표시, 여행 삭제 |
| 선택 (시간이 남으면) | 캐리어 완성도 연출 (FR-08) |
| 향후 확장 | 회원가입·로그인, WebSocket 실시간 갱신, AI 기반 추천, 날씨 API 연동, CI/CD·IaC, 데이터 자동 만료 |
| 제외 | 결제, 항공·숙박 예약, 지도·경로 안내, 설치형 모바일 앱 |

## 4. 기능 요구사항

| ID | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| FR-01 | 여행 생성 | 국내/해외, 이동수단, 기간, 계절과 닉네임을 입력해 여행을 만든다. 공유 코드와 주최자 토큰이 발급된다. | 생성 직후 공유 코드와 준비물 목록이 화면에 보인다. |
| FR-02 | 준비물 추천 | 입력한 조건에 맞는 준비물 목록을 분류별로 자동 생성한다. | 조건을 바꾸면 추가되는 항목이 달라진다. |
| FR-03 | 코드로 참여 | 공유 코드와 닉네임으로 입장하고 토큰을 발급받는다. | 올바른 코드로 입장하고, 잘못된 코드는 오류 안내가 나온다. |
| FR-04 | 준비물 관리 | 참여자 누구나 항목을 추가하고, 주최자가 항목을 삭제한다. | 변경이 다른 참여자 화면에 반영된다. |
| FR-05 | 담당자 지정과 완료 체크 | 항목마다 담당자를 지정하고, 담당자가 완료로 체크한다. | 담당자와 완료 상태가 새로고침 후에도 유지된다. |
| FR-06 | 팀 진행률 | 전체 완료율과 참여자별 완료율을 보여준다. | 체크하면 진행률이 갱신된다. |
| FR-07 | 여행 삭제 | 주최자가 여행과 관련 데이터를 삭제한다. | 삭제 후 같은 코드로 입장할 수 없다. |
| FR-08 (선택) | 캐리어 완성도 | 분류별 완료 정도를 캐리어 그림으로 보여준다. 새 API 없이 진행률 데이터로 화면에서 계산한다. | 체크 상태에 따라 그림이 바뀐다. |

화면 갱신은 5초 간격 폴링으로 한다. 같은 항목을 동시에 수정하면 마지막 저장이 적용되며, 비어 있는 항목을 동시에 맡으면 먼저 맡은 사람만 성공한다.

## 5. 사용자 흐름과 화면

### 흐름

```
[시작]
 ├─ 여행 만들기 → [생성: 조건 + 닉네임] → [체크리스트] (공유 코드 표시)
 └─ 코드로 참여 → [참여: 코드 + 닉네임] → [체크리스트]
 (이전에 들어간 여행은 브라우저에 저장된 토큰으로 바로 이어서 연다)
```

### 화면

| 화면 | 구성 |
|---|---|
| 시작 | 여행 만들기, 코드로 참여, 내가 들어갔던 여행 목록 |
| 생성 | 국내/해외, 이동수단, 기간, 계절 선택과 닉네임 입력 |
| 참여 | 공유 코드와 닉네임 입력, 잘못된 코드면 안내 문구 |
| 체크리스트 | 여행 조건 요약, 공유 코드와 복사 버튼, 전체·참여자별 진행률, 6개 분류별 항목(담당자, 완료 체크, 내가 맡기), 항목 추가 |

- 주최자에게만 보이는 것: 항목별 담당자 선택, 항목 삭제, 여행 삭제
- 모든 화면은 `index.html` 한 파일 안에서 전환한다. CloudFront 사용자 지정 오류 응답을 쓰지 않으므로 다른 경로로 이동하지 않는다.
- API 오류는 코드별 안내 문구와 재시도 버튼으로 보여준다. 토큰이 없거나 무효이거나 여행이 없으면 저장된 토큰을 지우고 입장 화면으로 보낸다.

### 반응형

| 화면 폭 | 배치 | 주 사용자 |
|---|---|---|
| 휴대폰 | 한 줄로 쌓는 배치 | 청중(참여자) |
| PC | 2단 배치. 오른쪽에 공유 코드를 크게, 그 아래 진행률 | 발표자(주최자), 프로젝터 화면 |

## 6. 추천 규칙

AI 없이 규칙으로 만든다. 공통 기본 목록(20~30개)에 조건별 추가 항목을 합치고 중복을 제거한다. 추천 목록은 앱 서버 코드 안의 정적 데이터(JSON)로 둔다.

| 조건 | 선택지 | 추가되는 준비물 예시 |
|---|---|---|
| 국내/해외 | 국내, 해외 | 해외: 여권, 환전, 유심·로밍, 멀티 어댑터. 국내: 신분증 |
| 이동수단 | 비행기, 자동차, 기차 | 비행기: 탑승권, 기내 반입 규정 확인. 자동차: 운전면허증, 차량용 충전기, 멀미약. 기차: 승차권 |
| 기간 | 당일, 1~2박, 3박 이상 | 기간이 길수록 의류·세면·상비약 항목 확대 |
| 계절 | 봄·가을, 여름, 겨울 | 여름: 선크림, 모자. 겨울: 핫팩, 장갑 |

준비물은 서류, 의류, 세면, 전자기기, 건강·안전, 기타의 6개 분류로 나눈다. 여행당 항목은 추천 항목을 포함해 최대 200개다.

## 7. 시스템 구성

```
브라우저 ─▶ CloudFront ─┬─(화면)────▶ S3 (비공개, OAC)
                        └─(/api/*)──▶ EC2 FastAPI (프라이빗 서브넷, 0.0.0.0:8000)
                                          │ 3306
                                          ▼
                                     EC2 MariaDB (프라이빗 서브넷)
```

| 티어 | 구성 | 핵심 설정 |
|---|---|---|
| 웹 | S3 + CloudFront | S3는 비공개이며 OAC로만 접근. 사용자 지정 오류 응답 없음 |
| 앱 | EC2(Ubuntu) + FastAPI | VPC 오리진으로 CloudFront 요청만 받음. systemd로 실행 |
| DB | EC2(Ubuntu) + MariaDB 직접 설치 | sg-app에서 오는 3306 연결만 허용. 앱 전용 계정에 최소 권한 |

- 인터넷에서 서버로 들어오는 길은 CloudFront뿐이고, 서버가 밖으로 나가는 길은 NAT Gateway 하나다.
- 서버 접속은 SSM Session Manager로만 한다(22번 포트 없음).
- DB 비밀번호는 Parameter Store에 두고, 저장소에는 비밀번호·키를 올리지 않는다.

## 8. API 요약

모든 API는 `/api` 아래에 있고, 토큰은 `X-Pack-Token` 헤더로 보낸다. 오류는 `{"detail": {"code": "...", "message": "..."}}` 형식이다. 요청·응답 형식과 오류 코드는 API 명세를 따른다.

| # | 메서드 | 경로 | 하는 일 | 호출할 수 있는 사람 |
|---|---|---|---|---|
| 1 | GET | `/api/health` | 서버 상태 확인 | 누구나 |
| 2 | POST | `/api/trips` | 여행 만들기, 추천 목록 생성 | 누구나 |
| 3 | POST | `/api/trips/{code}/members` | 코드로 참여 | 누구나 |
| 4 | GET | `/api/trips/{code}` | 여행 전체 상태 조회(5초 폴링) | 그 여행의 참여자 |
| 5 | POST | `/api/trips/{code}/items` | 항목 추가 | 그 여행의 참여자 |
| 6 | DELETE | `/api/trips/{code}/items/{item_id}` | 항목 삭제 | 주최자 |
| 7 | PUT | `/api/trips/{code}/items/{item_id}/assignee` | 담당자 지정·해제 | 참여자(자기만), 주최자(누구든) |
| 8 | PUT | `/api/trips/{code}/items/{item_id}/done` | 완료 체크·해제 | 그 항목의 담당자 |
| 9 | DELETE | `/api/trips/{code}` | 여행 삭제 | 주최자 |

## 10. 완료 기준과 리스크

### 완료 기준

FR-01~07이 CloudFront 주소에서 끝까지 동작하고, 수동 구축·배포 절차가 문서대로 재현되며, 보안 기본값이 적용되면 완료로 본다.

- 기능: 여행 생성부터 참여, 담당·체크, 진행률, 삭제까지 휴대폰과 PC에서 끝까지 동작한다.
- 보안: 두 서버는 공인 IP 없이 프라이빗 서브넷에 있고, S3는 비공개이며, 저장소에 비밀번호·키가 없다.
- 운영: 백업과 복원 방법을 확인했고, 백업 시연 영상이 있다.

### 주요 리스크

| 리스크 | 대응 |
|---|---|
| 기능 욕심으로 일정 지연 | FR-01~07 외에는 손대지 않는다. FR-08은 3일 차 저녁에 진행 여부를 정한다. |
| 콘솔 구축 지연 | 1일 차에 네트워크까지, 2일 차에 두 서버와 DB 연결까지 끝낸다. |
| 설정은 맞는데 연결이 안 됨 | `bind-address`, uvicorn `--host 0.0.0.0`, S3 OAC 버킷 정책, 사용자 지정 오류 응답, `X-Pack-Token` 원본 요청 정책 다섯 곳을 먼저 확인한다. |
| 자격 증명 유출 | 장기 액세스 키를 만들지 않고, DB 비밀번호는 Parameter Store에 둔다. |
| 발표 중 시연 실패 | 4일 차에 백업 영상을 녹화하고 발표장 네트워크를 미리 점검한다. |

## 11. 데모 시나리오

청중이 휴대폰으로 직접 참여하는 것이 데모의 중심이다.

1. 발표자가 PC에서 여행을 만든다(예: 해외, 비행기, 1~2박, 여름). 준비물 목록과 공유 코드가 나온다.
2. 공유 코드를 프로젝터 화면에 띄우고, 청중이 휴대폰으로 코드와 닉네임을 입력해 입장한다.
3. 청중이 항목을 맡고 챙긴 항목을 체크한다.
4. 발표자 화면에서 팀 진행률이 올라가는 것을 보여준다.
5. 조건을 바꿔(예: 국내, 기차, 당일, 겨울) 새 여행을 만들고 목록이 달라지는 것을 보여준다.
